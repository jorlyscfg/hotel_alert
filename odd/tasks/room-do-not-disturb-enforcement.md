# Room Do Not Disturb Enforcement

## Objective
Enforce room-level Do Not Disturb for customer service requests, keep its area-console indicators consistent with registered ROOM-station assignments, and notify every AREA console immediately when a room's DND state changes with audible cues and background OS notifications, without a foreground popup for each transition.

## Problem and Why
The room DND flag is persisted and exposed, but a client can still submit service requests while it is enabled. The area snapshot also includes active DND rooms without checking for a currently registered ROOM station, and a room can retain DND after its station is moved or removed. Native AREA consoles currently acknowledge `room.updated` without refreshing their snapshot, and DND changes have no request-like visual/system notification; active-room chips are also too tall and low-contrast. Separately, token-authenticated browser API requests send same-origin cookies too, while the server rejects cookie-plus-bearer requests as ambiguous credentials; this can surface as the screenshot's generic invalid-credentials message when an AREA console starts a request.

## Authorized Scope
- Disable room service actions while DND is enabled and reject new requests for a DND room on the server.
- Show active DND rooms in area consoles only when a non-retired, active ROOM station remains assigned to that room.
- Clear the former room's DND state when its station is reassigned, deactivated, or retired; publish the room update so clients refresh the indicator.
- Refresh native AREA station snapshots on `room.updated`, so DND changes reach the area console without requiring a restart.
- Keep service and area controls visibly disabled during DND while allowing taps to open an explanatory modal; preserve server-side request rejection.
- Polish the DND explanation modal per the supplied screenshots: hide its visible title, promote the requested instruction to heading size, ensure CTA contrast, and avoid repeating a room code already present in its localized name in the AREA DND strip.
- Deliver room DND activation and deactivation to every AREA console immediately and play an audible notification for each actual state change, using the existing durable `room.updated` flow and shared AREA tone where possible.
- Restyle the active DND room chip with a red background and white text/icon, and reduce its height while preserving its room label and accessible status.
- Play a localized AREA sound cue for each actual DND activation/deactivation without opening a foreground visual popup/modal; keep the active-room indicator. In the native Android console, post the equivalent OS notification only when the app is backgrounded; it must not expose a request-start action. Suppress initial snapshot hydration, duplicate/replayed events, and unrelated room edits.
- Do not send same-origin admin cookies alongside device bearer tokens from the browser API; keep cookie credentials for cookie-authenticated admin calls.
- For native AREA stations, send request transitions through the native command bridge that owns the device token; never call the browser API with an empty browser-stored token.
- Add/update focused tests with the behavior. No Android notification-policy, schema, or unrelated UI changes.

## Acceptance Criteria
- A room with DND enabled cannot start a new request from the client UI, and the server rejects a direct request attempt.
- Turning DND off restores the normal service-request flow.
- Area snapshots list only active DND rooms assigned to active, non-retired ROOM stations.
- Moving, deactivating, or retiring the ROOM station clears DND on the room it leaves and emits the room-state update; the room no longer appears in the area DND list.
- A native AREA station refreshes its snapshot after `room.updated`, and displays the active DND room without restarting.
- During DND, room service/area controls have a disabled visual and accessible state but still respond to taps by showing a localized explanation modal; no request dialog or request is opened.
- The DND explanation modal has no visible title, displays `Desactive "No molestar" para poder solicitar servicios.` at the former title size, and has a clearly contrasted action button while retaining an accessible dialog name.
- An AREA DND room entry does not repeat the room code when the resolved localized name already contains it; distinct room names remain visible.
- Actual DND activation and deactivation are reflected in every connected AREA console without polling or restart, including native AREA stations, and cause one audible notification per observed state transition; initial snapshot load and unrelated room changes do not sound.
- Each active DND room chip has a red background with white text/icon and reduced vertical height; localized room names remain readable.
- Every actual DND activation/deactivation produces one audible cue without a foreground AREA popup/modal; initial snapshot load, replay/duplicate events, room metadata edits, and snapshot hydration produce none.
- A background native Android AREA console receives a DND OS notification without request-start actions; a foreground console keeps the active-room indicator and sound but opens no DND popup/modal.
- Device-token browser requests omit ambient admin cookies, and admin cookie-authenticated calls still include credentials; mixed auth can no longer cause ambiguous-auth failures on the AREA request transition path.
- A paired native AREA station starts/accepts requests through its native command bridge; browser-only stations continue using the browser API with their stored device token, and no path sends an empty bearer token.
- ROOM request-confirmation and AREA incoming-request alerts keep the same request tone; DND activation/deactivation use two distinct, recognizable tones in foreground web AREA and background native AREA, distinct from the request tone.
- Existing unrelated worktree/index content remains untouched.
