# Server image processing runtime

The server image normalizer requires FFmpeg on the server host. Install it as an operating-system runtime dependency and make `ffmpeg` available on `PATH`, or set `FFMPEG_PATH` to the executable. The deployed FFmpeg build must include decoders for the image formats the hotel intends to accept; support is codec-build-dependent.

The processor reads uploaded bytes from stdin and emits a normalized image on stdout; it does not use the uploaded filename or MIME type and does not create temporary files. Output defaults to lossy WebP at quality 80 (quality range 1–100) with alpha retained; callers can explicitly request PNG when lossless output is needed. It applies JPEG EXIF orientation and FFmpeg rotation metadata, processes only the first frame of animated images, strips source metadata, and supports centered `cover` cropping or transparent `contain` fitting. Hard limits are 50 MiB input, 24 million decoded pixels, 4096 pixels per output dimension, 10 MiB normalized output, and 15 seconds per conversion. Callers may lower these per-request limits, but cannot raise the processor ceilings. Decoder details are not returned in processing errors.
